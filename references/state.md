# 状态感知

每次交付（status / radar / study / record done / record mood）末尾都带一句：「状态：X（信号）。建议：…」。脚本算的，直接用；可以换成用户的口吻，不加新判断。今天的必做已勾时建议不会再指向它。

## 信号
- 客观（脚本从 state.json 和 Canvas 快照算）：上次「做完了」距今几天；本周必做勾了几件；连续几天有必做没勾；已过期未交；48 小时内未交的 deadline；7 天内到期的权重合计；14 天内有没有考试。
- 主观（AI 听到就记）：用户说「没状态 / 累 / 不想学 / 来不及 / 太多 / 焦虑 / 卡住 / 不会 / 看不懂 / 病了」→ `record mood <原词>`。7 天内有效，只往上抬一档。

## 四档
- 过载：7 天内到期权重 ≥40%，或 72 小时内 ≥3 条 deadline。
- 卡住：有已过期未交，或连续 3 天必做没勾。
- 落后：周四起本周勾了不到四成，或上次勾距今 >4 天且本周有必做。
- 正常：其余。
- 病了：单独处理，建议休息，给延期申请的路径（Canvas 课程页找 Special Consideration / Extension），可以替用户起草两句给老师的消息。

## 建议库
- 过载：只留必做，按权重排，今天只做最急一条的第一步，15 分钟就停；交不完的先问能不能延期。
- 卡住：把任务缩到一个动作；不会做就问卡在哪一页课件，指给用户看；没开始就用五分钟规则。
- 落后：本周清单砍到「上课前要看的」最小集，周末补一件；今天先做必做。
- 正常：一句肯定 + 下一步；临近考试提一句「从今天起每天过一周的课件」。

## 怎么说
一句，不评价人。用户说了状态差就别再问「为什么」，直接给建议里的第一个动作。用户说「不用」就 `record decision "…"`，以后不提。
