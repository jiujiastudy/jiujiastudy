# 本周该学什么

## 命令
`collect --touch`（10 分钟内采过就直接用上次的）→ `study --write`：脚本用元数据排好（每门课三桶 + 每天一件必做），写 `plans/<ISO周>.json`、`plans/<周>.md`、`reports/周报_<周>.html`，并复制成资料夹根目录的「本周清单.html」（用户看这份），登记 INDEX 和日志。只看不写：`study`。想换周：`study --week 8`。

## 脚本怎么排
- 数据：模块条目（名称、类型、锁定、解锁时间、链接）、作业（截止、分值、提交状态、类型）、7 天内公告、手动 deadline。不读课件正文。
- 周次识别，四级回退：模块名（Week 7 / Wk 7 / W7 / Module 7 / Class 7 / 第 7 周）→ 条目标题 → 本周解锁 → 认不出就标 ⚠️ 并给模块链接。识别方法写在每门课的 `detect` 字段。
- 三桶：上课前要看的（页面 / 课件 / 视频）、要做的练习或小测（小测 / 讨论 / 本周内到期作业）、与 deadline 相关的事（14 天内 deadline + 已过期未交）。每项：编号（2001-2）、动词、时长估计、第一步、来源、状态。
- 排天：计分作业到期前 1–2 天当必做（权重 ≥10% 提前 2 天）；考试前 3 天每天「复习一周的课件」；每门课的核心课件排上课日前一天（不知道上课日就周一到周四轮流）；其余进应做（每天 ≤2），装不下的进先搁着；周日「收工」。
- 本周最要紧的一件：未交且 7 天内权重最高 → 已过期未交 → 本周小测或讨论 → 离 deadline 最近那门课的第一份课件。
- 末尾附状态一句和上周复盘（上周做了几件、没做的挪本周还是先搁着，只问一次）。

## AI 负责的润色（可选）
脚本的措辞是通用的；要更贴用户，写一份覆盖层再跑 `study --write --zh 文件`：
```json
{"days": {"2026-09-16": {"must": "…", "must_first_step": "…", "must_if_then": "…", "should": ["…"]}},
 "courses": {"MKTG2001": {"topic": "市场细分", "before_class": {"2001-2": {"first_step": "先看第 12–20 页"}}}},
 "top": [{"course": "…", "title": "…", "when": "…", "why": "…", "first_step": "…"}],
 "review": "…", "mantra": "…"}
```
能用公告里的具体信息（考试带 ID、教室改了）就写进对应课程的 topic 或 first_step。不改结构，不加脚本没有的项。覆盖层的 top[0] 会同步成「本周最要紧的一件」，控制台、md、HTML 一致。

## 打勾（record done）
「做完了」→ 今天的必做；「做完了 2001-2」→ 那一项；「✓ 09-16」→ 那天；「2001 看完了」→ 那门课本周「上课前要看的」全部；「全部」→ 今天以前的都勾。「没做」「跳过」→ 什么都不改，不追问。命令会打印「✅ …，明天：…」和状态一句，照着回。周计划的 HTML 和 md 自动重生成。

## 考试
14 天内有考试或小测（quiz 类型，或名字含 exam / test / quiz / 考试）：考前 3 天的必做自动变成「复习 Week a–b 的课件」，状态一句也会提。用户要复习包（单元 / 单词 / 模拟题）就用 toolbox.md 里的渲染器做。

## 手写计划
plans/ 里已有同名、不是脚本生成的计划：`study --write` 会另存为 `<周>.auto.json`，不覆盖；确定要覆盖加 `--force`。

## 学习页和课程说明（有就接上，没有照旧）
- 周报不等学习页：读 `<档案>/learn/<ISO周>/<课>.json`（学习页清单，见 learn.md）。有清单的课，「课前看」换成学习页的分块（每块能打勾，点标题跳到那一节），学习页查到的上课时间进「每天」的固定时间，带截止的要学生做的事挂在截止前一天；做好后 Canvas 又多了新条目、新解锁的课件或新公告，课程卡上提示一句「更新 X 学习页」，只提示不重做。
- 没有清单、清单坏了、学习页文件被删了、清单是上周的：都当这门课没有学习页，照旧列模块条目，卡片底下一句怎么要（这周什么都没有的课不提）；上周那份给一个折叠链接。两门以上没有时，页头下面推荐先做哪一门（截止最近的那门，脚本挑，换宿主也挑同一门）。
- 学习页的分块照「在哪节课之前」排进具体哪天（早上的课前一天看、下午以后的课当天能看），每天学习页最多 `study.daily_minutes` 分钟（默认 120；学生说「每天学习页改成 150 分钟」就 `config set study.daily_minutes 150`）；排不下的进先搁着并写原因，截止在下周的写「下周初再看」。页头一行学习页总量：一共多少、这周排进多少、先搁着多少。
- 模块没按周分的课（detect 是 none，周报写「没按周排，这周讲什么还没对上」的那种；只放考试的站不算）：`outline 课 --syllabus` 或 `outline 课 --url <课程说明网址>` 读一遍，认出每周题目存进 `<档案>/outline/<课>.json`；核对认错的地方，补上 weeks_zh（每周一句中文），用 `outline 课 --file 表.json` 存回。有表以后周报写「这周讲：…（中文）· 出自课程说明第 N 周」，不再让学生去主页找。
- 命令输出末尾的「还差 N 件」是给 AI 的：只列补得上的事和现成的命令（模块没按周分还没建每周安排表、学习页清单有问题、保底清单上没读过的外部平台、Moodle 上没读到日期的作业测验：逐个读作业页，照 moodle.md）。先回答学生，回答完再照着补（宿主能开后台就放后台）；补到新作业、新截止，或者周报要改的，再跟学生说一句并刷新周报。学生的页面上不出现，也不跟学生说「还差」。试过补不上的（网页打不开、认不出每周安排）7 天内不再列。
- 外部平台：每门课的外部链接（保底清单，`external 课` 看）来自已采集的模块、近 14 天公告（标题写到这周的旧公告也算）、快到期作业的说明，加上去 Canvas 查到的导航栏、课程首页和相关课程页面（每个班各一个的只留学生自己班的）。这一查每门课 7 天一次，采集完自动在后台跑，开场不等它；没跑成的，「还差 N 件」里列一条 `external 课`。公告、作业说明、导航栏、课程页面里的链接，按周分模块的课这周模块里的，不按周分的课模块里的，没读过就进「还差 N 件」（`browse 网址 --course 课`）；整学期都在的资源站、会议链接、表单不进。可能有作业和截止的平台（Ed、Gradescope、Piazza……）这周试过没读到，课程卡上写一句情况：「这次没读到 Ed，Ed 上这周有没有新作业还不确定，下次会再试。」
