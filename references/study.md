# 本周该学什么

## 命令
`collect --touch`（10 分钟内采过就直接用上次的）→ `study --write`：脚本用元数据排好（每门课三桶 + 每天一件必做），写 `plans/<ISO周>.json`、`plans/<周>.md`、`reports/周报_<周>.html`，并复制成资料夹根目录的「STCanvas.html」（用户看这份），登记 INDEX 和日志。只看不写：`study`。想换周：`study --week 8`。

## 脚本怎么排
- 数据：模块条目（名称、类型、锁定、解锁时间、链接）、作业（截止、分值、提交状态、类型）、7 天内公告、手动 deadline。不读课件正文。
- 周次识别，四级回退：模块名（Week 7 / Wk 7 / W7 / Module 7 / Class 7 / 第 7 周）→ 条目标题 → 本周解锁 → 认不出就标 ⚠️ 并给模块链接。识别方法写在每门课的 `detect` 字段。
- 三桶：上课前要看的（页面 / 课件 / 视频）、要做的练习或小测（小测 / 讨论 / 本周内到期作业）、与 deadline 相关的事（14 天内 deadline + 已过期未交）。每项：编号（2001-2）、动词、时长估计、第一步、来源、状态。
- 排天：计分作业到期前 1–2 天当必做（权重 ≥10% 提前 2 天）；考试前 3 天每天「复习一周的课件」；每门课的核心课件排上课日前一天（不知道上课日就周一到周四轮流）；其余进应做（每天 ≤2），装不下的进停车场；周日「收工」。
- 本周最要紧的一件：未交且 7 天内权重最高 → 已过期未交 → 本周小测或讨论 → 离 deadline 最近那门课的第一份课件。
- 末尾附状态一句和上周复盘（上周做了几件、没做的挪本周还是停车场，只问一次）。

## AI 负责的润色（可选）
脚本的措辞是通用的；要更贴用户，写一份覆盖层再跑 `study --write --zh 文件`：
```json
{"days": {"2026-09-16": {"must": "…", "must_first_step": "…", "must_if_then": "…", "should": ["…"]}},
 "courses": {"MKTG2001": {"topic": "市场细分", "before_class": {"2001-2": {"first_step": "先看第 12–20 页"}}}},
 "top": [{"course": "…", "title": "…", "when": "…", "why": "…", "first_step": "…"}],
 "review": "…", "mantra": "…"}
```
能用公告里的具体信息（考试带 ID、教室改了）就写进对应课程的 topic 或 first_step。不改结构，不加脚本没有的项。覆盖层的 top[0] 会同步成「本周最要紧的一件」，控制台、md、HTML 一致。

## 打勾（record done）
「做完了」→ 今天的必做；「做完了 2001-2」→ 那一项；「✓ 09-16」→ 那天；「2001 看完了」→ 那门课本周「上课前要看的」全部；「全部」→ 今天以前的都勾。「没做」「跳过」→ 什么都不改，不追问。命令会打印「✅ …，明天：…」和状态一句，照着回。周计划的 HTML 和 md 自动重生成。

## 考试
14 天内有考试或小测（quiz 类型，或名字含 exam / test / quiz / 考试）：考前 3 天的必做自动变成「复习 Week a–b 的课件」，状态一句也会提。用户要复习包（单元 / 单词 / 模拟题）就用 toolbox.md 里的渲染器做。

## 手写计划
plans/ 里已有同名、不是脚本生成的计划：`study --write` 会另存为 `<周>.auto.json`，不覆盖；确定要覆盖加 `--force`。
