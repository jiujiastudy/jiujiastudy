# deadline 雷达

## 命令
`collect --touch`（拉作业、模块、公告、站内信；默认不下载课件；10 分钟内采过就直接用上次的，`--force` 重拉）→ `radar --write`（写机器档案里 DDL雷达.md 的标记块，HTML 写到资料夹根目录的 Deadline雷达.html，登记 INDEX 和日志）。只想看不落盘：`radar`。`radar --fetch` 先快速采集再出。

## 结构（脚本已排好，照着复述）
1. 每门课下一条：每门课最近的一条，14 天内没有就说没有。
2. 🔴 最急的一条 + 第一步（按提交类型：上传 → 看文件格式和命名；小测 → 看时长和可试次数；讨论 → 看字数；课上交 → 确认时间地点）。
3. ⚠️ 撞车：48 小时内 ≥2 门课有 deadline，带合计权重。
4. 区块一 已确认：Canvas 的截止时间（没有 due_at 但有 lock_at 的标「锁定时间当截止」）和你记的手动 deadline。
5. 区块二 待确认：Canvas 没写日期的计分作业、小测、考试，从公告 / 说明推的，用户说过「日期只是占位」的，用户还没确认的。定义写在标题里：以 Canvas 和老师为准。
6. 已过期未交：此刻往前 21 天内已过、计分或是小测、没提交（可能是课堂活动或线下交，以 Canvas 为准；`record note` 说明过的不算）。
7. 新变化：最近一次采集的新公告、作业改动、出分、新解锁。脚本给英文摘录，回答时用中文说要点。
8. 状态一句。

## 怎么说
复述 1、2、3 和区块二里今天要做决定的；其余说「完整表在资料夹的 Deadline雷达.html」。时间写「09-25 周五 18:30，还有 11 天」。剩余这一列按课程所在时区数天：今天 / 明天 / 还有 N 天 / 已过期（今天早些时候过的）/ 已过 N 天；过没过期按真实时刻算，不是按日历日。课程时区和用户电脑时区此刻不同时，脚本会并列写两个（先课程时区），照抄。

## 日期不对、Canvas 没写的（都有命令，别手改 state.json）
- Canvas 上的 due 只是占位（公告说「system demands a date」、课上讲的作业、锁定时间当截止）：`record note <作业id> "Canvas 的 09-13 只是占位，实际 Week 7 课上讲"`。作业 id 在作业链接末尾（/assignments/123456）。之后这条不算过期，进区块二带着说明。
- 真实日期从公告 / 大纲 / 老师那里来：`record deadline "Class Pitch 本人上场" --course MKTG2001 --due 2026-09-15 --time 16:00 --weight 15% --url <作业链接> --status "课上讲" --source "公告 09-11"`。给了 `--url`（或 `--assignment-id`）指向 Canvas 那条作业时，雷达用手动的替换 Canvas 那行。没到确认的加 `--pending`（进区块二）。
- 两来源冲突：记两条都 `--pending`，计划按较早的排；老师答复后再记一条不带 pending 的，并 `record resolve` 对应的待确认。
- 从公告 / 说明里挖到但还要用户去查的：`record pending "内容" --course 课 --blocks 2026-09-20 --ask-en "…" --ask-zh "…"`。
- 需要老师答的，附两行英文 + 中文意思 + 路径（Canvas → Inbox → Compose，选课程和 tutor）。这是事务性消息，直接替用户起草。
